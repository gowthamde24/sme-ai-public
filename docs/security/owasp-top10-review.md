# OWASP Top 10 (2021) review of the API (job CB, 2026-10-12)

Scope: `services/ai-api`, the database policies it relies on, and the public edge. The web app is reviewed by its own lane. Each row names the control, the evidence (a test or a file) and any gap. "Gap" items are on the pre-pilot checklist.

| # | Category | Controls | Evidence | Gap / follow-up |
|---|---|---|---|---|
| A01 | Broken access control | Every tenant-owned table has RLS; every client-callable function checks membership and role inside the database; routes depend on a verified user; privileged actions need a second factor (aal2). The API never uses a service-role key for a person's request. | pgTAP RLS and allow-list files (06 and the per-table files); `tests/test_cb_hardening.py::test_public_route_inventory` fails on a new route without sign-in; tenant-isolation integration tests | The worker account's powers are listed in pgTAP 79 |
| A02 | Cryptographic failures | Provider secrets are `SecretStr`, entered at run time, never stored in plain text or logged; capability tokens (calendar feed) store only a SHA-256; webhook signatures verified with constant-time compare; HSTS in production; secret scan in `check-fast` | `tests/test_cb_secret_scan.py`; config tests; connector signature tests (BZ) | Encryption at rest and TLS are the hosting provider's |
| A03 | Injection | All data access is PostgREST or `rpc` with bound parameters; no SQL strings built from input in the API; dynamic SQL in functions uses `format(%I/%L)`; spreadsheet cells are sanitised against formula injection on export; inbound e-mail, pages and documents are untrusted text and are never executed as instructions | eval suite (T006), CSV sanitiser tests, `test_migration_copies_*` pins | The load-test helper builds one SQL string from slugs it generated itself (validated by regex) |
| A04 | Insecure design | Approval gates for external sends, prices and deletions; deterministic pricing; per-day cost caps and quotas in the database; the real-data gate; fail-closed configuration (production refuses to start with missing keys) | ADRs 0013, 0019, 0066; pgTAP 49 (cost cap), 90 (research quotas) | |
| A05 | Security misconfiguration | Docs/OpenAPI off outside development; explicit CORS origins, no credentials, no DELETE; security headers; `server` header removed; request body ceiling; production config validation | `test_cb_hardening.py` (docs gating, CORS, headers, body limit) | Hosting: TLS, proxy hops, metrics token (checklist) |
| A06 | Vulnerable and outdated components | `pip-audit` of the 46 installed packages: 0 known; `npm audit --omit=dev`: 0; full `npm audit`: 5 high, development-only (eslint-config-next chain) | Report `job-cb-report.md` | Re-run before launch and monthly; CI job proposal |
| A07 | Identification and authentication failures | JWTs verified (signature, issuer, audience, expiry) against the project keys; second factor for privileged actions; failed-sign-in slow-down per address; sign-up limits; MFA recovery runbook | auth tests; `test_cb_hardening.py` (limiter, slow-down) | Password policy and e-mail confirmation are Supabase Auth settings (hosted-auth-settings runbook) |
| A08 | Software and data integrity failures | Migrations append-only and reviewed; copied-function pin tests; audit log (append-only) of business actions; webhook payloads verified before use; no deserialisation of untrusted pickles/YAML | pin tests; audit tests | CI supply chain (pinned versions, lockfiles): lockfiles are committed |
| A09 | Security logging and monitoring failures | Access line with request id, route pattern, status, timing, hashed caller; scrubbed logs; agent runs and approvals audited; `/ready` and `/metrics` | `test_cb_hardening.py` (access line, scrubber, metrics) | No alerting is wired: a hosting step (checklist) |
| A10 | Server-side request forgery | The only outbound fetches are the guarded fetcher (scheme, port, DNS and redirect checks, private ranges refused, size/time limits), the web-research handle store (a page is read only from a handle or an owner-typed link), and fixed provider hosts | T007 fetcher tests; BP tests | |

## Public (no sign-in) routes
`/health`, `/ready`, `/metrics` (404 without the token), `/v1/policies/current`, `/v1/calendar/feed/{token}.ics`, and the webhooks of the connectors (secret path or signature). Each has a per-IP limit.
