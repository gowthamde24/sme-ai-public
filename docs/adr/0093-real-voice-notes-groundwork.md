# ADR 0093: Real voice notes on WhatsApp: Sarvam behind the interface, coded as OGG/Opus by ffmpeg

Status: **built and tested locally (job DJ, night run C1, 2026-10-25); nothing deployed; no account opened; no key exists; no call to Sarvam was made.** Real voice notes stay OFF everywhere until the owner creates a Sarvam account and key and a native speaker has reviewed a voice (docs/runbooks/voice-notes-real.md). Builds on ADR 0071 (the voice interface), ADR 0088 (voice notes and their fair-use meter), ADR 0084 part 4, ADR 0076 (WhatsApp), ADR 0087 (children's data), ADR 0017.

## Context
Owner decision (23 Oct 2026): the speech provider is **Sarvam** (Bulbul for text to speech, Saarika/Saaras for speech to text) behind our interface; **WhatsApp voice notes first** (no telephony yet). Job CV had built voice notes with the fake provider only; the Sarvam adapter already existed from job BD (ADR 0071) but nothing joined it to a note: its audio is a WAV, WhatsApp plays no WAV, and a voice had no provider-side name.

## Decisions
1. **Which speech a voice note uses** (`VOICE_NOTE_TTS_PROVIDER`, the worker's setting): `auto` (default) = Sarvam when `SARVAM_API_KEY` is set; else the older `VOICE_TTS_PROVIDER` when it names one; else **the fake provider in development, and no speech at all in a deployment** (every message then goes as text, as before). `off`; `fake` (development only: a fake tone must never reach a real customer); `sarvam` (needs the key AND ffmpeg). A real provider without ffmpeg **stops the process at start** rather than silently sending text for ever. No test and no default opens a socket.
2. **The speech request** (`SarvamTts`, checked against docs.sarvam.ai on 2026-10-25): `language_code` is `te-IN`, `hi-IN`, `kn-IN`, `en-IN` (and `ta-IN`); the model is `bulbul:v3`; the codec asked for is **WAV** because Bulbul v3 refuses `opus` (the page says so); the text is at most 2,500 characters (a note is at most 600); `speaker` is the voice's own name; `pace` is the business's speed (0.75 to 1.25, clamped to the provider's 0.5 to 2.0); the rate is 24 kHz. An answer that is not exactly one clip is refused. Errors are constant codes: no key, text or audio is in an error, a log or a `repr`.
3. **Coding for WhatsApp** (`app/voice/convert.py`): ffmpeg, as a child process with FIXED arguments (no shell; the audio goes in on stdin and the result comes out on stdout, so no file is written and nothing is stored), 20-second timeout, mono, 16 kHz, Opus at 24 kbit/s, metadata dropped. The result is checked (an Ogg page, then an `OpusHead` with one channel). WhatsApp takes `audio/ogg` only with the Opus codec and mono input, 16 MB at most (Meta's media page, read 2026-10-25); the clip is sent as `audio/ogg; codecs=opus`. **Not confirmed from Meta's pages:** what makes WhatsApp draw the clip as a "voice message" (the waveform, the microphone badge) rather than as an audio file; check it with a real number once the owner has a test number. The seconds on the fair-use ledger are measured on the provider's own WAV before coding. If coding fails nothing is recorded and the text goes alone.
4. **The images (owner decision 25 Oct 2026: ffmpeg in the worker's image only):** `deploy/Dockerfile.api` has three stages: `base` (everything shared), `worker` (adds Debian's `ffmpeg`, `--no-install-recommends`; ffmpeg 7.1.5 in the current base) and `api` as the LAST stage, so a plain `docker build` makes the small API image and `--target worker` the worker's. Cloud Build takes `_TARGET` (`deploy/cloudbuild-api.yaml`); `deploy/cloudrun.sh worker` builds and deploys its own image `worker:<tag>` (a Cloud Run job, so its size touches no user-facing cold start); `deploy/staging.sh` builds all three. `make container-smoke` proves the API image has no ffmpeg and the worker image codes a tone as OGG/Opus mono. Measured sizes: see the job report (API image 74 MB as before; worker image 239 MB).
5. **A voice is data, with its provider and speaker.** `voice.voices.speaker` (migration 20261128090000) names the provider's voice; `public.scheduler_voice_plan` now also answers the chosen voice's `provider` and `speaker`. The only door for a real voice is `app.operator_register_voice(code, provider, language, label, speaker, reviewed_by)`: a real voice nobody listened to is refused by the table's CHECK (job CV), and the fake provider cannot be added that way. **No Sarvam voice is registered by this job**: which speaker suits Telugu, Hindi, Kannada and English is for a native speaker to decide by listening. The worker speaks a voice only with the provider it belongs to (a Sarvam voice is never spoken by the fake provider and the other way round); otherwise the text goes alone. The business's choice per language (`voice_choices`, the Owner with a second factor) and its speed are as before.
6. **Languages:** Telugu, Hindi, Kannada and English (and Tamil, which the product already has) go to the provider as themselves; the spoken AI-disclosure line is per language and must be reviewed by a native speaker before it is spoken over real data (job CV, unchanged).
7. **The child-name rule holds, structurally.** A voice note is the words the Owner approved: a campaign's text with only the fields `name`, `amount`, `due_date`, `reference` and `business` (the database refuses any other: a campaign with `{{child_name}}`, `{{student}}`, `{{child_label}}`, `{{admission_no}}` or `{{programme}}` cannot be approved), preceded by the disclosure. No code on the speech path (the converter, the Sarvam adapter, the factory, the hook) names a child column or the education tables (a test reads the sources), and nothing is stored: the audio is held in memory for one send.

## Consequences
* New settings `VOICE_NOTE_TTS_PROVIDER`, `VOICE_NOTE_FFMPEG`; `TextToSpeech.synthesize` takes optional `speaker` and `pace` (the other providers accept and ignore them); the WhatsApp adapter accepts `audio/ogg; codecs=opus`; CI installs ffmpeg and sets `REQUIRE_FFMPEG=1` so the converter's real-ffmpeg tests cannot be skipped there.
* Not built: speech to text for incoming voice notes (WhatsApp customers' voice notes are still not read; ADR 0076), telephony (calls), a speaker catalogue, a listening panel for the reviewer, the unit price of Sarvam per note in the plans' cost model (assumptions are in `scripts/usage_assumptions.json`, job DI), pronunciation dictionaries (`dict_id`) for names and amounts.
* Price (Sarvam's page, as recorded by job BD): about Rs 3 per 1,000 characters for Bulbul v3; a 300-character note costs about Rs 1. Re-check before approving spend (ADR 0017).
