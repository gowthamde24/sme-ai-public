# ADR 0071: voice groundwork (speech to text, text to speech, a voice route) and the router's safety net

Status: accepted for the local stage (job BD, 2026-10-11). Builds on ADR 0013 (agent runs and their cost ledger), ADR 0064 (the allowance, "fair use") and ADR 0070 (the tool router). Nothing is deployed; no account has been opened; no key exists in the repository.

## Context
The owner's shop talks in Telugu, Hindi, Kannada and English, and many people would rather speak than type. Before choosing a speech engine we need to (a) put speech behind one interface so an engine is a small adapter, (b) measure the candidates on the family's own voices, and (c) have a voice route that is ready but OFF. Separately, the tool router of ADR 0070 hides the catalogue and visit tools from most questions; a question phrased without a trigger word would get a refusal for something the assistant could do.

## Decisions
1. **One interface** (`app/voice/interface.py`): `SpeechToText.transcribe(audio, content_type, language, keyterms) -> Transcript` and `TextToSpeech.synthesize(text, language) -> Speech`. Errors carry a constant code only (timeout, unreachable:Class, http_NNN, bad_response, no_speech, unsupported_audio ...): never a provider's words, an address or a key. Audio and transcripts are never logged. A **fake** adapter (no socket) is what tests use.
2. **Adapters, each switched on only by its own environment variables** (`VOICE_STT_PROVIDER` / `VOICE_TTS_PROVIDER` = off | fake | sarvam | bhashini | google | ai4bharat; keys `SARVAM_API_KEY`, `BHASHINI_API_KEY` + service ids, `GOOGLE_API_KEY`, `AI4BHARAT_STT_URL` / `AI4BHARAT_TTS_URL` + `AI4BHARAT_TOKEN`). OFF by default; a provider named without what it needs stops the process at start; `fake` is development only. Keys are entered hidden by the owner (`read -rs`), live only in the environment and in a request header (never in an address), and are `SecretStr` in settings. Sarvam, Bhashini and Google follow their public documentation; the AI4Bharat adapter speaks a plain documented contract to an address the owner runs (there is no public AI4Bharat endpoint with a stated free tier). Bhashini's text-to-speech request has not been run against the live service.
3. **`POST /v1/tenants/{id}/assistant/voice`** (Owner, Admin, Sales; 503 `voice_unavailable` unless a speech-to-text provider is configured). The body is the recording; query `message_id`, optional `conversation_id`, `language` (hint), `speak`. The container is read from the first bytes (WAV, M4A / MP4, WebM, Ogg, FLAC, MP3), at most **60 seconds** (exact for WAV and M4A; 1.5 MB for the others) and 12 MB on the wire; nothing is decoded or stored. The transcript becomes the owner's message and goes through the **existing** flow (`start_message`, shared with `POST /assistant/messages`); the answer streams as server-sent events with a leading `transcript` event and, when asked and configured, a trailing `audio` event (base64) or `audio_error`. **Audio is never stored** (held in memory for the request); the transcript is stored only as the chat already stores a message. A retry names the same `conversation_id` (as for text); a replay speaks and charges nothing new and does not call the speech engine again (see the addendum).
4. **Fair use.** Speech has no tokens, so two accounting models in the AI ledger carry it (migration `20261112090000_bd_voice_prices.sql`): `voice-stt` (10 tokens a second of audio) and `voice-tts` (4 tokens a character), priced at the table's ceiling, 1,000 micros a token: **Rs 0.60 a minute and Rs 4 per 1,000 characters**, a little above the dearest price found (Sarvam Rs 0.50 and Rs 3), so the allowance is never undercounted whichever provider is on. They go through `agent_reserve_cost` / `agent_record_usage`, so the daily and monthly caps, the pause and the usage screens count them. The charge is made before the provider is called; the allowance is read first (`ai_paused_until`), so a used-up workspace is refused (429) before any audio leaves the machine. A spoken answer is at most 500 characters. Because the question and the spoken answer are charged to the SAME run, a run that carries voice may be charged up to **Rs 3.00** in all, for its voice charges only (see the addendum: the run's own budget for the model stays Rs 1.00); token budgets, tool-call limit, life, hourly run limit and the workspace caps are unchanged.
5. **The bake-off** (`make stt-bakeoff`, extended): reads `.wav` / `.m4a` from `~/Desktop/voice-samples/` (outside the repository), the language from the file name (`te-01.m4a`), the owner's typed `.truth.txt`; runs every configured adapter; reports word and character error, median time per request, the list price per minute and the estimated cost of the run (refused above Rs 100 unless `CONFIRM_SPEND=1`), per language; speaks a few reference sentences through every configured text-to-speech adapter and saves the audio for listening. The report goes to `~/Desktop/v2-overnight/voice-bakeoff.md`; the tool refuses a report or a folder inside the repository.
6. **The router's safety net** (`app/assistant/router.py`, `runner.py`). If the model calls a tool the router did not offer, and the question (or the chat so far) carries a WEAK signal for that group (a saree word, a verb of sending, a day or a time, in the five languages), every tool is offered once and the call proceeds; if the model refuses to help while a hidden group could have, one more model call is made with every tool and a fixed note. At most once per question; both cost a normal model call, counted like any other. Each miss is logged as `assistant router miss: tool=<name or none:group> language=<code>` and nothing else, so the word lists can be improved from real misses. A question with no weak signal gets no second chance.

## Consequences
* New: `app/voice/*`, `app/assistant/routes.start_message` (the shared start), the voice route, a runner hook (`on_reply`) that lets the voice route speak the answer while the run is still open, one migration, pgTAP 49's price list and `test_voice.py`, `test_voice_api.py`, an extended `test_stt_bakeoff.py`.
* Risks listed in the job BD report: the transcript is as private as a typed message but the recording goes to a third party when a provider is on (each provider's retention terms are in the report; Sarvam's workspace default keeps data until the Owner sets zero retention);  the Bhashini and AI4Bharat text-to-speech requests are untested against live services; the weak-signal lists are written without native readers.
* No dependency was added (httpx and the standard library).

## Addendum (job BD review): the budget by path, and a retry does not call the engine again
1. **The assistant run's cost budget is back to Rs 1.00 for every run** (migration `20261113090000_bd_voice_run_budget.sql`; the earlier migration is not edited). A run that carries voice (it has a reservation of the `voice-stt` or `voice-tts` accounting model; there is no flag a caller can set) may be charged up to **Rs 3.00 in all**, for its voice charges only. Mechanism: `agent_record_usage` is replaced as a full copy (pinned by `test_migration_copies_bd.py`). The run's own counter `cost_micros_used` (held by a table check to `max_cost_micros`) keeps counting only what the MODEL spends, which stays held to the run's own budget exactly as before; a voice charge is on the ledger and the step but not in that counter and is held, with the model's spending, to `greatest(max_cost_micros, 3,000,000)`. The early check of a reported cost uses the larger ceiling only for a run that carries voice. A text run behaves exactly as before. pgTAP 82 tests both paths (and 9 hand mutations of the function are killed); `test_voice_api` proves a text question runs with Rs 1.00 and a spoken one passes Rs 1.00 on the ledger only because it carries voice.
2. **A replay does not call the speech engine again.** When the message id is already the caller's own user message in this business (read through the caller's token, so only their own chats are visible), the stored words are reused as the transcript (`reused: true` in the transcript event), the recording is only checked and dropped (never stored), nothing is charged, and the shared start replays the stored answer. A message id that is not the caller's own is not reused: the engine is used and the shared start refuses the id (409 `message_id_used`) as it does for text. A retry works even when the allowance is used up, because it spends nothing.
