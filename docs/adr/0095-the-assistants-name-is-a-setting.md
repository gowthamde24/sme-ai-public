# ADR 0095: the assistant's name is a setting, never a word in the product (job DN)

Status: accepted (owner, 25 Oct 2026: "Replace every user-visible 'Agent OWL' with the workspace's assistant name from Settings > AI assistant, default Vijaya, read through one helper, never a literal"). Follows ADR 0094, which retired the owls; this retires the name that went with them.

## Decisions
1. **One placeholder, one default, one helper.** A string says `{assistant}`; `lib/assistant/name.ts` is the only file that writes the default name (`DEFAULT_ASSISTANT_NAME`, "Vijaya") and gives `currentAssistantName()` and `withAssistantName()`. Client safe. A test (`lib/assistant/no-literal-name.test.ts`) fails if "Agent OWL", "Vijaya" or the old sample name "Vani" is written in shipped code (comments aside), the string files, the pack texts or the static pages.
2. **The name of the request.** `getLang()` (every page and layout asks for the language before it draws a word) also fixes the name for the request: inside the app (an address under `/app/`, read from the `x-sme-path` header the proxy already sets) it is the name the owner saved in Settings > AI assistant, else the default; everywhere else it is the default. It sits in a React `cache()` slot (`lib/assistant/request-name.ts`), so two workspaces never see each other's name, and a layout and a page of one request, which render side by side, prime the same value. A read that fails leaves the default: a name never stops a page from drawing.
3. **Words are resolved where they are drawn from.** `appDict`, `siteDict`, `legalDict` and `authDict` build their dictionaries per language AND name (`namedDict`, at most 40 entries), so `wordsFor`, `frameLabels` and the 25 `*-words.ts` files give the client parts words that are already right; `fill()` and `fillLegal()` put the name into any other text. The client `word()` helper fills `{assistant}` of an English fallback with the default.
4. **Where the name does not follow the workspace.** The public site, the legal pages, the sign-in screens and the manifest are for people who are not in a workspace: they say the default (the legal texts and the home page's voice example say `{assistant}` too, so they change in one place). The offline pages are static files and say no name. Server actions and route handlers do not prime a name; none of them writes the assistant's name into a customer's message.
5. **The settings tab that was called "Agent OWL" is "Automation"** (sending switches, reminders, the scheduler's status); the AI assistant has its own tab.
6. **What is not changed.** The API's seven agent keys, the ADRs and migrations that name the old product (history), and the `description` of the `today` module in `packages/packs/modules.json`, which is copied into an append-only migration and is not shown to anyone.

## The Ask dock
The question line of Today (`AskTeam`, variant `hero`) is also drawn at the bottom of the list screens of the menu (`components/v2/app/today/ask/AskDock.tsx`, mounted by the workspace's layout), only when the assistant can be asked (its state is idle or working, read once per request with `readAgentsCached`, shared with Today). Not on Today (it has its own), nor on Settings, forms, a single record or the live call. The component arrives as a chunk of its own when the page is idle, so the route-JS budgets count only the bar and the address check.

## Not done / for the owner
- The real name will come from C1's assistant-settings API; only `readAssistantName` in `lib/assistant/source.ts` changes then. Until `ASSISTANT_SCREENS` is on, every workspace says "Vijaya".
- The legal texts changed in wording (the assistant is now `{assistant}`, "Vijaya" on the public pages). `LEGAL_VERSION` was NOT bumped, because the API holds its own list of known terms versions; a bump and the API's list have to move together.
