# ADR 0105: the assistant talks the way people talk (job DS, Part 0 of night 4)

Status: built on branch `api/ds-spoken-style` (27 Oct 2026). Source: the owner's feedback of 26 Oct (a native Telugu speaker): the listening samples sound like "an AI reading pure bookish Telugu"; customers talk everyday Telugu with English words mixed in. The problem is mostly the TEXT we generate (the written register, for example "మాట్లాడవచ్చా", "అసిస్టెంట్‌ని"), and partly the voice settings.

## Decision
1. **A speaking style per workspace and per language** (`public.speaking_styles`, `GET/PUT /v1/tenants/{t}/speaking-style`): `everyday_mixed` (DEFAULT: how people talk, with the English words people use), `everyday_pure` (spoken, fewer English words), `formal` (the written register, only if the Owner wants it). Optional region: Telugu coastal / telangana / rayalaseema, Tamil chennai / kongu, Kannada bengaluru / north_karnataka; the default is neutral spoken. Every member reads it (the prompts need it); the Owner sets it with a second factor.
2. **A register block in every prompt that writes words for a customer** (`app/agents/register`): rules in English (short sentences, spoken verb forms, the polite particle, English nouns kept in English in Latin letters, numbers said the way people say them, no Sanskritised words), the language's own rules, an optional region hint, and **seven of the owner's example lines** as few-shot (copy the register, not the facts). The WhatsApp reply draft uses it now; the call-turn prompt of the comparison uses it; the call pipeline will read the same function when telephony exists. A setting that cannot be read never stops a message: the default is used.
3. **The examples come from files the owner can edit** (`app/agents/register/data/native_lines/<lang>.md`, copied from `~/Desktop/stack19-jobs/native-lines/`). **Telugu is the owner's own approved text.** hi, kn, ta, ml and en are drafts written on the model of the Telugu file, marked `draft` in the API (`examples: "draft"`) and in the prompt; a native reader replaces them.
4. **The fixed sample lines everyone sees** (the assistant introduction and the nine preview samples of the AI-assistant settings) are rewritten in the same spoken style in all six call languages. "assistant" now stays in Latin letters in every language ("AI assistant ని", "AI assistant बोल रही हूँ"), as the owner's own line has it.
5. **The voice:** Sarvam Bulbul v3 reads code-mixed text in one string, so the text goes as people write it (English words in Latin letters inside the sentence), pace 1.08 (was 0.95 warm / 1.1 crisp), the default temperature, the same speaker as the earlier samples (`ritu`) so only the text and the pace differ. Preprocessing is automatic on v3 (docs.sarvam.ai). Translation modes (formal / modern-colloquial / code-mixed) are not used: no line here is produced by translation; if one ever is, use the code-mixed / modern-colloquial mode.
6. **A "spoken register" rule in the comparison** (`app/agents/compare.py`, rule 9): a reply that contains one of a small list of known written forms per language fails it. The list is data (`data/register.json`), deliberately short; it is a tripwire, not a judge of wording. `make register-ab` answers the comparison conversations with Claude Haiku (only) with and without the block and reports the written forms, the other rules and the English words kept.
7. **Listening samples:** `make voice-samples-spoken` renders six lines in each of te, hi, kn, ta, ml (the opening with the AI disclosure, the saree follow-up, a price answer, "call me later", a polite "not interested", a school admission reply) with a page that sets the earlier bookish lines beside them. HARD CAP 3,000 characters (2,599 used), kept in `voice-samples/spoken/usage.json`.

## Consequences
- The prompts grow by about 1,500 characters per call; the block is built once per message.
- Nothing about prices changes: the draft prompt still forbids an amount in a WhatsApp message and the outbox word check is unchanged.
- The owner (Telugu) can edit `te.md` and the style takes effect on the next deploy; other languages wait for a native reader.
