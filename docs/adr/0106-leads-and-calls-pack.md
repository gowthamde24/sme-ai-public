# ADR 0106: "Leads & calls" for any business: nine business types as data, a lead playbook, a knowledge base (job DR / A1)

Status: built on branch `api/dr-leads-pack` (night run 27 Oct 2026), stacked on `api/ds-spoken-style` (#118), which is stacked on #114-#117. Source: the owner's decision "any business with leads" (night4-c1.md).

## Decision
1. **The nine business types are ordinary packs** (`packages/packs/<id>/pack.json`, status `preview`: selectable at sign-up with the label "Not validated by a real owner yet"): `real_estate, coaching, clinic, insurance_loans, auto_dealer, interiors_solar, travel, gym, wholesale_b2b`. They switch on the generic modules only (today, inbox, contacts, enquiries, followups, visits, campaigns, call_list, voice_notes, reports, office, integrations; companies for wholesale). No code names them (the "no pack id in code" check still holds; three pre-existing lists of institution kinds hold the literal `coaching` and are allow-listed with the reason). The three deep packs are unchanged and have no template.
2. **A template is data next to the pack** (`packages/packs/<id>/leads.json`, checked by `scripts/packs_check.py` against `leads.schema.json`): the goal of the call (a closed code, named in four languages), up to 8 questions each filling a contact custom field of the pack (the captured fields are the pack's `custom_fields`, which already exist and are created for a workspace that takes the pack), up to 8 objections with an honest answer, the follow-up timings (retry by call, WhatsApp after a conversation, a reminder BEFORE a booked time as a negative offset), the reasons an outcome can carry, and the safety rules of the kind of business. It is English: the assistant says it in the customer's language in the everyday spoken style (ADR 0105). **A template states no price, no promise, no guarantee** (the checker and the API refuse it), and the sensitive kinds say so in their safety rules (a clinic never asks about symptoms; insurance and loans never promise approval or ask for PAN/Aadhaar/OTP; coaching never promises results or takes a child's marks).
3. **The Owner edits the template, not the platform's rules** (`public.lead_playbooks`, `GET/PUT /lead-playbook`): goal sentence, a subset and order of the pack's fields as questions, objections, follow-ups, outcome reasons; saved by the Owner with a second factor; the safety rules are not editable. A reset returns to the template.
4. **The knowledge base:** the Owner pastes text or uploads a brochure, price list or FAQ (PDF, Word, text; base64 in JSON because this API takes no multipart); **only the text is kept, never the file**. The model drafts facts (one run of the assistant: platform switches, run limits, the worst-case cost reserved and the real usage recorded; the text reaches it only as UNTRUSTED data between a per-run delimiter); every fact is a DRAFT until the Owner or an Admin approves it; an edit sends it back to draft. **The assistant may only state approved facts. A price is a fact of kind `price`: text that looks like a price can only be a `price` fact (a CHECK in the table), and only the Owner with a second factor approves one.** The WhatsApp reply draft receives the approved facts WITHOUT the price facts (a WhatsApp message states no amount; the outbox money check is unchanged); the call and task prompts take `facts_block(..., allow_prices=True)`.
5. **Reading files without a new dependency:** plain text/Markdown/HTML, Word (the zip and its XML by regex, with a decompression cap), and PDFs with real text (the standard library, best effort). A scanned PDF or a picture needs an OCR/vision reader behind the `DocumentReader` interface; **none is configured** (503 `reader_unavailable`: "type or paste it instead"; a fake reader exists for tests). The file type is decided by its first bytes, not its name.
6. **The model for drafting facts is the `ask` job's model** (Claude by default; the setting refuses Sarvam for that job, ADR 0102).

## Consequences
- `GET /v1/packs` lists twelve business types; the sign-up screen groups the nine under "Any business with leads" (the web lane).
- The accent token `leads_orange` is new (the web falls back to its default look until art exists); each type has its own owl prop token and `PackCard.tsx` maps them to stand-in lucide icons.
- Telugu, Hindi and Kannada names and the goal labels are drafts for native review; Tamil and Malayalam are not in a pack file (packs carry four languages).
- A pack version is never edited after its migration is on main; a change to a template is a new version.
