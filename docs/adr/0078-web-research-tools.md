# ADR 0078: web research tools for Agent OWL (search, read a page, find retailers, metal prices)

Status: accepted for the local stage (job BP, 2026-10-12). Builds on ADR 0013 (agent runtime), ADR 0017 (local-first, no paid dependency without written approval), ADR 0063/0071 (the AI ledger and voice as an accounting model), T007/T007b (the guarded page fetcher).
Migration `20261119090000_bp_research_tools.sql`; pgTAP `90_bp_research_tools`; runbook `docs/runbooks/web-research.md`. Nothing is deployed, no account is opened, no key exists in the repository.

## What was built

Four tools for the Main agent (Agent OWL), each behind an interface with a fake, each switched on only by an environment variable the owner sets later:

| Tool | Interface | Real adapters (official APIs only, no scraping) | Fake |
|---|---|---|---|
| `web_search` | `SearchProvider` (`app/agents/web.py`, from T007b) | Tavily, Brave Search | `DemoSearch` |
| `read_page` | `PageFetcher` (T007) | the existing guarded fetcher (`WEB_FETCH=real`) | the fixture fetcher |
| `find_retailers` | `PlacesSearch` | Google Places API (New), Text Search | `FixturePlaces` |
| `get_metal_prices` | `MetalPrices` | Metals.dev | `FixtureMetals` |

Not built: a GSTIN verification vendor (see 7) and a change to the Research agent (see 8).

## Decisions

1. **Off by default; offered only to a question about the web.** A tool whose provider is not configured is never described to the model. Even when configured, the deterministic router (ADR 0070) offers the web group only for a question that contains a web word in one of the five languages, a gold or silver rate or price phrase, a retailer or wholesaler phrase, or a pasted `http(s)` address (or when the chat just before did). The word lists need a native reader.
2. **A web call is a metered call on the AI ledger, like voice (job BD).** Four accounting models priced at the table's 1,000 micros a token: `web-search` 600 tokens (Rs 0.60), `web-page` 50 (Rs 0.05), `places-search` 3,000 (Rs 3.00), `metal-price` 100 (Rs 0.10). These are fair-use measures a little above the dearest published price (Tavily Rs 0.7 a credit at pay-as-you-go, Brave Rs 0.4 a request, Google Places Pro about Rs 2.7 a call after its free monthly allowance), not an invoice. They are reserved before the call and settled after, in the run, so the workspace's daily and monthly caps, the pause and the usage screens already count them. A call that provably never reached a provider (a key refused, a rate limit, a quota answer, a page the guard refused before the network) is released as not billed. `public.agent_record_usage` was replaced as a full copy of BD's (pinned by `test_migration_copies_bp.py`): every `voice-%` test became `app.is_metered_model`, and the voice-only ceiling of Rs 3.00 became `app.metered_ceiling(tenant, run)`, still Rs 3.00 for voice only and Rs 8.00 once the run used a web tool (voice 3.00 plus the worst case of one question: 3 searches 1.80, 2 pages 0.10, 1 places search 3.00, 1 metal price 0.10). The model's own spending stays held to the run's own budget.
3. **Limits.** Per question: 3 searches, 2 pages, 1 places search, 1 metal price. Per workspace per India cost-day, by call count: 30 searches, 60 pages, 10 places searches, 20 metal prices (`research.web_caps`, operator-owned, `public.web_quota_take`, SQLSTATE `SM251`). A call released as not billed does not count. The limit is soft: two calls at the very same instant can both pass.
4. **Web content is untrusted data, never instructions.** Results are reduced to bounded plain text (markup, control and direction characters out; only plain http(s) addresses without credentials), shown to the model between the usual random delimiters. There is no tool that sends, approves, prices, spends or deletes, and the action tools are not even offered to a web question unless the router would have offered them anyway; a model that obeys an injected instruction is refused (tested). Answers cite sources (`web`, `place`, `metal_price` with an address); a web page's rupee amount cannot be repeated (the answer's money check allows only amounts a tool returned); the metal price can, and is labelled "reference only, not the owner's price list".
5. **A query leaves the building, so it is checked** (`app/websearch/guard.py` and `public.web_query_check`): 3 to 200 characters, no e-mail address, no phone number (seven or more digits, phone shapes), no link; and no full name (four or more characters) of a person who is a non-erased contact of the business. Company names are allowed. The model is told this, but the rule does not rest on it.
6. **`read_page` takes a handle, never an address the model wrote.** It accepts the handle of a result this run's search returned, or an address the owner typed in the question word for word. A page cannot send the model somewhere new or carry data out in a link. The fetch itself is the T007 guarded fetcher (robots.txt, SSRF guard, size and time limits, contact details removed).
7. **GSTIN verification is not built against a vendor.** The GST portal's public "Search Taxpayer" is behind a captcha and has no public API; verified lookups are sold per call by GST Suvidha Providers and resellers (for example annual plans from about Rs 3,500 for 5,000 calls and trials of 5 to 50 calls, read from a reseller's page in 2026; unverified, and no vendor's terms were reviewed). That is a paid dependency, which ADR 0017 reserves for the owner's prior written approval. `app/websearch/gstin.py` holds only the interface and a fake. Format and checksum validation are offline and belong to job CA.
8. **The Research agent is not changed.** Its evidence rule (`agent_write_evidence` accepts a web page only on the company's OWN website host) is a database rule from T007 and is the reason a third-party search result could not become evidence; search results would be context only, and a claim needs an evidence quote. Adding a search tool to that sandbox means a new `ToolContext` field, runtime wiring, a scripted-model branch and new containment evals for little gain. The decision for the owner: if third-party pages should ever count as evidence, that is a change to the evidence rule and its review (ADR 0013), not to this job. The tools are plain functions over the interfaces and can be offered to it later.
9. **Google Places terms.** Read on 2026-10-12 (sources below): a place ID may be stored indefinitely; other Places content (names, addresses, links) is not to be stored beyond Google's short cache allowance, and must be shown with Google's attribution. Therefore: a search returns names and addresses **to be shown now**, as cards with a link to the place on Google Maps (the client must show Google's attribution next to them: see the web contract); only the place ID is ever written to the database; in the stored answer text the place's name and address are replaced by "(see the cards)"; a lead is created only by `POST /places/confirm` from the details **the owner types** (name, city, region), with source `places:<place id>`. The request asks only Pro-tier fields (id, name, address, map link, status), never Enterprise fields (phone, website, rating, reviews): `PLACES_FIELD_TIER=ids` asks for ids only (the free tier) and shows no names. Closed-permanently places are dropped. Two things were NOT verified: the Maps Service Specific Terms page was truncated when read, so the exact caching allowance (a third-party summary says latitude and longitude up to 30 days) is not relied on, and nothing is cached; and whether the app's screens satisfy the attribution rule is for the web lane to confirm with the current Google policy page.
10. **Search provider terms.** Tavily returns results and an answer for a query; the request here asks `search_depth: basic` (1 credit), no answer and no raw content. Brave's terms say storing results needs a plan that explicitly grants storage rights; here nothing from a result is stored as a record (only the text of the answer and the page address the answer cites). That is the minimum that lets the owner check an answer later; confirm it against the plan chosen before switching Brave on.
11. **Metal prices** come from Metals.dev (`/v1/latest?currency=INR&unit=g`; documented delay of up to 60 seconds; cached 15 minutes in memory). The figure is the international spot-based price converted to rupees per gram, not the jewellery, retail or IBJA rate; it is shown as a reference with its time and source, never enters a price list or a quote (non-negotiable 4), and the quote engine never reads it. Free-plan quota and caching terms were NOT verified.

## API

`GET /v1/tenants/{t}/research/status` (Owner, Admin): which tools are switched on and today's use against each daily limit. `POST /v1/tenants/{t}/places/confirm` (Owner, Admin, Sales): make a company and a lead from a shop found on the map, ids derived from the tenant and the place ID (idempotent; a different name for the same place is 409). The assistant's source events gain `kind` `web | place | metal_price` and an optional `url`. **Job CE:** a `place` source also carries `place_id`, Google's own place ID exactly as the Places API sent it (the stable uuid in `id` is made from it and stays for the handle); it is sent live with the card, never stored (a stored chat's sources leave places out, a replay has none), and null for every other kind. The Find retailers screen sends it unchanged as `place_id` to `POST /places/confirm`. Both ends accept 10 to 90 letters, digits, `_` and `-` (the lead's source `places:<ID>` must fit its 100 characters), and the search shows only places whose ID fits, so a card shown can always be confirmed.

## Consequences and risks
* Web sources are not persisted as source pairs (the database accepts only in-app types), so a stored answer's web citations survive only as the "From the web:" line in its text; a place's name does not survive at all (by design).
* The Rs 8.00 run ceiling is a fair-use bound, not a cost: an assistant run that uses every tool and speaks its answer is still held to it.
* The daily limit is by call count per workspace, not by money; the money cap (ADR 0063) still applies on top.
* No provider has run live; the request shapes follow the providers' documentation read on 2026-10-12 and are tested against recorded-shape fake servers only.
* Router words for the web group in Hindi, Telugu, Kannada and Tamil need a native review.
