# VoiceLink: the telephony provider of Stack19 (owner decision 24 Nov 2026: "we will go with VoiceLink only"). Setup, in order. C1, 26 Nov 2026.

Plivo is dropped (its code stays dormant). Everything below is VoiceLink. **There is no Saturday gate: the owner tops up as soon as he can and the steps run from there.**

## What is built (and tested against a fake VoiceLink; no real call has happened yet)
| part | where | what it does |
|---|---|---|
| Inbound | `app/telephony/voicelink_routes.py` `/v1/telephony/voicelink/ws/{token}` | VoiceLink opens our WebSocket bot when a call reaches our number; base64 A-law 8 kHz; events connected / start / media / mark / clear / transfer / stop; the workspace is found by the number (a `phone_numbers` row, provider `voicelink`). The token is the secret in the address (VoiceLink signs nothing). |
| Dynamic inbound | `/inbound_call/{token}` | for a number that VoiceLink is told to ASK us per call: we answer `ws_url` + `webhook_url`. Optional; the static bot works without it. |
| Outbound call-backs | `app/telephony/voicelink_api.py` + the existing placer | the task dialer / the Owner's test call go through the SAME gate as before (calling hours 9-21, consent / STOP / do-not-call, per-day and per-week limits, the sandbox list, the fence, billing), then `POST /add_lead` (10 digits, `country_code` 91, our row id in `custom_parameters`). When the person answers, VoiceLink opens our bot with that id: admitted only against a waiting row of ours. |
| Webhook | `/webhook/{token}` | call.initiated records VoiceLink's call id on the row; call.ended closes a call nobody answered (no answer / busy / failed) so the dialer moves on; an answered call is finished by its own call session. |
| Wallet | `VoicelinkApi.wallet()` + the daily balance check | read once a day; below the limit (default Rs 500, `PROD_VOICELINK_MIN_INR`) a "Needs you" item appears in the staff console, and it says how many **days of cover are left**: the balance divided by the average daily cost of the calls of the last 7 days (our own cost ledger; the monthly number and channel fees are not in it, so they come on top; with no calls in the 7 days it says so instead of a number) (and a WhatsApp to the owner's own number when `PLIVO_BALANCE_ALERT_TO` is set: the setting keeps its old name). |
| Cost | `TELEPHONY_COST_PAISE_PER_MINUTE=50` (outbound), `TELEPHONY_COST_PAISE_PER_MINUTE_INBOUND=25`, `TELEPHONY_COST_PULSE_S=60` | VoiceLink (we are a registered reseller; prices excl. GST) bills per 60-second pulse counted from the answer, an unanswered call is free: **Rs 0.25 a minute inbound, Rs 0.50 outbound**, Rs 99 a channel a month, Rs 299 a number a month. The ledger costs each call by its direction at those rates (an inbound call with the inbound setting unset falls back to the one rate). Minutes (and the free cap) are counted by the call session, unchanged. |

**What no document tells us, and the first real calls will (we do not ask VoiceLink's support for message samples: the call log answers it, reports/voicelink-first-call-checklist.md):** which of `from` / `to` VoiceLink puts in the start of a call WE placed (the route accepts either), whether our `mark`s come back, what `transfer` carries, the exact `callStatus` words of the webhook (unknown words close a row as "failed", never as success), and whether `did_number` wants the 91 in front (we send it, as their number list shows). Each shows up in the first call's log lines, which carry closed words and no numbers.

**Plivo's A2P e-mail, replaced by (one line):** VoiceLink's documents name no A2P e-mail; their only compliance step is a use-case request with `dlt_confirmed=1` for the 140-series numbers, so a normal landline or mobile number needs none; we do not ask VoiceLink about a TRAI declaration (owner decision, 26 Nov 2026): our own rules (consent, the enquiry within 7 days, do-not-call/STOP, calling hours) apply whatever VoiceLink says, and if a real call shows a specific problem the owner asks then, with the call log.

## The owner's steps (his hands, money or accounts; each is a click or a hidden prompt)
1. **Top up** the VoiceLink wallet (minimum Rs 5,000; the test uses about Rs 900 of it; the number and channel fees come out of it each month) and send the planner the link/account he is using.
2. **Buy ONE number and TWO channels** in the VoiceLink portal (Rs 299 + 2 x Rs 99 = Rs 497 a month, excl. GST): a landline (080 or 022 as decided 12 Nov) if offered, else a mobile one. Tell the planner the number (E.164). **Why two channels:** a channel is ONE live call at a time for the whole reseller account (shared by every business on it), while a number belongs to one business; our limit is `TELEPHONY_MAX_CONCURRENT=2` (two calls at once), so two channels are needed. With one channel a second simultaneous call finds the line busy (more channels can be added later in the portal; raise the limit only after buying them).
3. **Create the bot** (portal: WebSocket Bot, `bot_name` Stack19). Its `websocket_url` and `webhook_url` are printed ONLY on a terminal by `deploy/voicelink-bot-url.sh production` (they hold the secret token); paste both into the form. Then map the number: inbound routing = that WebSocket bot, outbound routing = WebSocket bot (value 3).
4. **His login, typed at the hidden prompts** of `deploy/prod-secrets-prompt.sh` (slots `sme-voicelink-username` and `sme-voicelink-password`; the bot token slot is generated for him). Never in chat.

## First OUTBOUND test: the switch, the fence, the steps, the stop rule (28 Nov 2026)
* **The one setting:** production `TELEPHONY_OUTBOUND` false -> true (declared in deploy/settings/production/api.env; deploy with `ALLOW_FLAG_CHANGE=TELEPHONY_OUTBOUND`). `TELEPHONY_MODE` stays `sandbox`.
* **Why it is safe (read in the code, app/telephony/gate.py `check_outbound`):** in sandbox mode the gate refuses any number that is not on the sandbox list (`not_on_sandbox_list`) before anything else about the call; `live` is refused without TELEPHONY_LIVE_CONFIRMED; no task or rule dials anyone (`TASKS_DIALER` is empty); the only way to place a call is the Owner's "Place a test call" (POST /v1/tenants/{t}/calls/place, Owner role), and it can only pick a number from the sandbox list (the picker shows masked numbers). A refused call is stored as a refused call with its closed word. So at most the 3 listed phones can ever ring.
* **Steps (owner, in the app, workspace stack19-practice, between 09:00 and 21:00 IST):** Calls > Place a test call > pick the phone (his own +919502380998 can RECEIVE; the brother's also) > language Telugu > Place. The phone rings; answer, say hello; the assistant opens after the person's first word; talk over it once; hang up. Expected log lines: checklist section 2.
* **Stop rule:** two failed or odd calls in a row -> stop, send the log lines. To switch outbound off: a declared-file PR setting TELEPHONY_OUTBOUND=false and the API deploy, or `deploy/production.sh rollback sme-api --execute` to the previous revision (inbound keeps working either way).
