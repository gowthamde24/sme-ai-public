### Fallback: if the assistant is down
Decision (owner, 11 Nov 2026): the fallback rings a **second phone** (named by the owner, entered later by hidden prompt), never the shop mobile.
- [ ] **Not yet decided for VoiceLink, said plainly:** the Plivo fallback Worker (`deploy/cloudflare-worker-plivo-fallback.js`) was for Plivo's Fallback Answer URL and is dormant. VoiceLink's documents say that when a dynamic-routing API does not answer, the call "falls back to the account's default routing (a fallback message or number), if configured"; whether the same holds for a static WebSocket bot that is down is not documented. The one-message-to-support step was dropped (owner, 26 Nov 2026), so this is a separate question the owner asks only if he decides to, before relying on a fallback: "if our bot is unreachable, can the number fall back to a second phone?", and set it in the portal. Until that is confirmed and tested with a real call (the API stopped on a scratch revision, the owner choosing the day), the shop's own phone ringing first is the only safety net.
