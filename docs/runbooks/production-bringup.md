# Runbook: bringing production up (owner approved the plan 11 Nov 2026; target: production up on 30 Nov, synthetic data only, real-data gate CLOSED, Lead Desk dialer OFF)

**Nothing here has been run.** Nothing touches production until the owner says go for each step. Legend: **[OWNER]** only the owner can (account, payment, password, secret, DNS, decision); **[C1 PREPARES]** the script or file exists, the owner presses; **[C1]** read-only checks the agent runs with the owner's addresses. Every secret is typed into a hidden prompt on the owner's own terminal; none ever appears in a chat, a file, an argument or a log. Staging is never touched: `deploy/production.sh` refuses staging ids.

Costs (approved baseline about USD 75 to 100 a month; no point-in-time recovery for now, daily backups only): Supabase Pro 25 (+ about 5 for the small instance), Cloud Run API min-instances 1 about 44, web and worker 0 to 15, build/secrets/logs 2 to 10. The Plivo inbound number rental is a quote still to be taken. Google for Startups credits may offset the Google part.

## Secrets (names; created in the production project's Secret Manager, each read only by the service account that needs it, grant on THAT secret only)
`sme-suppression-hmac-key` (generated by `deploy/cloudrun.sh secrets`, never shown) · `sme-scheduler-password` (hidden prompt) · `sme-resend-api-key` · `sme-anthropic-api-key` · `sme-sarvam-api-key` · `sme-cartesia-api-key` · `sme-plivo-auth-id` · `sme-plivo-auth-token` · `sme-exotel-stream-secret` (it signs the per-call media token for Plivo too; generate 32+ random characters) · optional `sme-telephony-sandbox-numbers` (the callers allowed in while the mode is `sandbox`). Production uses NEW keys: staging keys are not copied. Service-role/database passwords never go to a service. `deploy/production.sh` refuses `--execute` while a required secret is missing.

## What production is (and is not) at first
* API: one instance, always warm (`MIN_INSTANCES=1`, `API_MAX_INSTANCES=1`: a live call lives on the server that answered it; more than one needs the routing in `docs/pre-pilot-checklist.md`). `TELEPHONY_MODE=sandbox` until the owner opens the gate AND says "live" in writing (then `PROD_TELEPHONY_MODE=live PROD_LIVE_OK=yes`). `TELEPHONY_OUTBOUND=false`, `TASKS_DIALER` empty (OFF).
* No WhatsApp Cloud API (owner, 11 Nov): the WhatsApp summary is a prepared text the owner sends from WhatsApp by hand. Outbox adapter: fake.
* Web flags: `deploy/production-web-flags.env` is empty on purpose; the web lane fills it in a reviewed PR. The staging file lists the owner's three TEST workspace ids and must not be copied.
* Hosting shape: `docs/runbooks/hosting-owner-runbook.md` and `hosting-env-and-secrets.md` stay the reference for every variable.

## Alerts (what `deploy/production-alerts.sh` creates; e-mail to the owner)
errors (any ERROR line in 5 min) · call failures (signature failures, a call that did not start or finish cleanly) · latency (p95 first sound above 3 s over 10 min, from the `phone_turn` log line) · no running API instance. Spend: Google budgets at 50/90/100 % (`deploy/budget-alerts.sh`), and the providers' own caps: Anthropic monthly hard cap, Cartesia grant balance, Sarvam top-up limit, Plivo balance alert. **Not proven on a real project**: the policy files follow Cloud Monitoring's documented shapes; the first `--execute` is the check, and each alert is triggered once on purpose.

## Failure drills before 30 Nov (each written down with the result)
1. Kill the API revision during a synthetic call: what the caller hears, whether the call row closes, whether the alert mails.
2. Wrong Plivo signature: the call is refused, `plivo_signature_failed` mails.
3. Roll back to the previous revision and forward again.
4. Supabase unreachable (wrong URL on a scratch revision, not live): the API answers a closed word, no stack trace.
5. Restore drill (step 4) re-run after the first week.
6. The 12 Nov swamp replayed (`call-capacity-and-instances.md`, 1g): slow data layer plus page fan-out during a synthetic call; the call has no audio gap, pages get `503 busy` in under 1 s.

## Stopping and rollback
`deploy/production.sh rollback sme-api [REVISION] --execute` (and `latest` to undo). Everything off: close the gate (`real-data-gate.md`), `AGENTS_ENABLED=false` redeploy, or set min-instances 0. Take the web down: delete the Cloudflare Worker's custom domain.
