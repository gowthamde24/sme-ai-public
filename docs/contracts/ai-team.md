# My AI team v2: the API contract (C1 -> C2; job ai-team-v2)

Status: **9 Nov 2026. Part T1 is built and real: the day (`GET /ai-team/day`) and the helper panel (`GET /ai-team/{helper}`). NOT built yet: the helper on/off switch, the panel's settings values, and the `paused` status. The stand-up (T2) is built too: text only, made by the worker at the business's opening time (section 3).** Job `~/Desktop/stack19-jobs/job-ai-team-v2.md`.

## What is real and what is not (C2: read this first)
| Part | State |
|---|---|
| `GET /ai-team/day`: lanes, marks, flow strip, cost, `needs_owner_total`, `status_now` (`busy`, `waiting`, `due`, `idle`) | **real**, every number from a real row (pgTAP 170 proves the ⚑ count equals Today's Needs-you) |
| `GET /ai-team/{helper}`: `status_now`, `recent`, `today.count` and `today.numbers`, `cost_today`, `train_href` | **real** |
| `PUT /ai-team/{helper}/switch`, the panel's `enabled`, `can_switch`, `reason_locked` | **not built**: not in the response. Do not show an on/off switch. |
| the panel's `settings` | **not built**: not in the response. Do not show a settings list. |
| `status_now.kind: "paused"` | **not built**: never sent |
| `GET/POST /ai-team/standup` | **real, text only** (section 3): the worker makes it at the business's opening time, from real numbers; `generated_at` is the real "Report ready" time. **Audio is not built** (Cartesia stays off): `audio` is always `null`, `audio_reason: "voice_off"`. |
- Base: `/v1/tenants/{tenant_id}`.
- Errors have the one shape `{error:{code,message,retry_after,request_id}}`.
- JSON is snake_case. Times are ISO 8601 with offset; the business's day is in **India time (Asia/Kolkata)**.
- Who: the Owner, an Admin and Sales read the day and the panels (a Viewer gets 403). The ⚑ marks follow Today's own role gates. The stand-up is read and generated by the Owner and an Admin.

## 0. The helpers
A closed list, in sales-flow order. `helpers` in `/ai-team/day` gives the ones **active in this workspace**: its pack, its modules and its connected sources decide which.

| `helper` | Lane name (en) | What its marks are |
|---|---|---|
| `lead_catcher` | Lead catcher | a lead arrived (website form, IndiaMART, e-mail, sheet, Meta, typed) |
| `lead_finder` | Lead Finder | a search ran; a business was found or called |
| `caller` | Caller | a call (inbound or outbound) with its length; a person asked for; a visit asked for |
| `followups` | Follow-ups | a follow-up message sent, or one due |
| `quote_writer` | Quote writer | a quote made, sent for approval, approved |
| `order_desk` | Order desk | an order made or moved on |
| `admissions` (school) | Admissions | an enquiry, a campus visit, an admission |
| `fee_reminders` (school) | Fee reminders | a fee reminder sent, a payment recorded |
| `notices` (school) | Notices | a notice or marks message sent |

School workspaces get `lead_catcher`, `caller`, `followups`, `admissions`, `fee_reminders` and `notices`. Every other workspace gets the first six (a helper the workspace cannot use is left out).

## 1. GET /ai-team/day?date=YYYY-MM-DD
`date` defaults to today; it may be up to 31 days back (else `422 date_out_of_range`). Owner, Admin, Sales. Target ≤ 300 ms p95 (measured: about 15 ms in the database for 1,600 marks). Cached 15 s per person and day, so polling every 20 s costs at most one read.
```json
{
  "date": "2026-11-06",
  "now": "2026-11-06T14:12:00+05:30",
  "day": { "opens": "09:00", "closes": "20:00", "source": "default" | "business_hours" },
  "lanes": [
    { "helper": "caller",
      "status_now": { "kind": "busy" | "due" | "waiting" | "idle", "text_key": "on_call" | "due_next" | "waiting_for_you" | "idle",
                      "count": 5, "at": "2026-11-06T16:00:00+05:30" | null, "who": "Ramesh" | null, "since": "2026-11-06T14:11:18+05:30" | null },
      "count_today": 23,
      "marks": [
        { "id": "phone_call:2b1c…", "t": "2026-11-06T10:42:07+05:30", "kind": "call", "seconds": 84 | null, "label": "Ramesh K · interested", "ref": { "type": "lead" | "call" | "quote" | "order" | "visit" | "prospect" | "prospect_search" | "student" | "admission" | "campaign", "id": "uuid", "href": "…" | null }, "needs_owner": false }
      ] }
  ],
  "flow": { "steps": [ { "key": "leads_in", "count": 41 }, { "key": "called", "count": 23 }, { "key": "interested", "count": 7 }, { "key": "quotes", "count": 3 }, { "key": "orders", "count": 1 } ],
            "extra": [ { "key": "fees_collected", "count": 4 } ] },
  "cost_today": { "paise": 18450, "calls_minutes": 31, "messages": 12, "ai_percent": 14 | null },
  "needs_owner_total": 4
}
```
- **`marks[].kind`:** `lead_in`, `search`, `found`, `call`, `message`, `followup_due`, `quote`, `quote_approved`, `order`, `visit`, `admission`, `fee_reminder`, `payment`, `notice`. The next `label` text is the item's own (a name and a short outcome word), never a model's.
- **`needs_owner: true` is the ⚑ orange mark** (today only; a past day has none).
  - A ⚑ mark's `t` can be **before the day**: it is something still waiting since then, such as a quote made yesterday. Pin it at the start of the axis with "since …".
  - Proven by pgTAP 170: for the Owner, an Admin and Sales, the ⚑ count equals Today's Needs-you count (top-up notices belong to no helper and are not counted), plus the Lead Finder businesses waiting for the Owner. The item waits for the Owner or a person. **The ⚑ marks of a lane are exactly the Needs you items of that helper**, so `needs_owner_total` equals the Today page's Needs-you count for those helpers.
- **Every mark is a real row.** `id` is `<table>:<row id>`; clicking opens `ref.href`.
  - At most **200 marks a lane**, newest kept; `count_today` is the true count.
  - Marks of a past `date` never change.
- **`status_now`** (only for today; `null` for a past date):
  - `busy`: "on call · Ramesh 0:42"; `since` is when the call started, so the timer runs on the web.
  - `due`: "5 due · next 16:00"; `count` is how many, `at` is the next one.
  - `waiting`: "1 waiting for you"; `count`.
  - `idle`.
  - The web words the `text_key` in en/te/hi/kn/ta/ml/mr.
- **`flow.steps`** is ordered and clickable (the web filters the timeline by the step's mark kinds).
  - **Business:** `leads_in`, `called` (distinct leads called), `interested` (calls with outcome interested), `quotes`, `orders`.
  - **School:** `enquiries`, `called`, `campus_visits`, `admissions`, with `fees_collected` in `extra`.
  - Counts are for `date`.
- **`cost_today`:** what the day cost. Call minutes and messages are counted; `paise` uses the plan's prices (`null` when the plan has no price for it); `ai_percent` is the share of the day's AI allowance. It is null for a past date beyond the usage kept. Owner and Admin only (`null` for Sales and Viewer).
- **`day`:** the business's opening hours for that weekday when set (Settings → Business hours), else 9:00–20:00. Marks outside the hours still come, so the web widens the axis.

## 2. GET /ai-team/{helper}
The side panel. Owner, Admin, Sales; `404` for a helper that is not active here.
```json
{ "helper": "caller", "status_now": { … as above … },
  "recent": [ { …a mark… } ],
  "today": { "count": 23, "numbers": [ { "key": "connected_percent", "value": 71 }, { "key": "interested", "value": 7 }, { "key": "minutes", "value": 31 } ] },
  "cost_today": { "paise": 9300 } | null,
  "train_href": "/ai-team/training" }
```
- `recent` holds the last 10 actions, newest first; they may come from earlier days.
- The `today.numbers` keys per helper:

  | helper | keys |
  |---|---|
  | `caller` | `connected_percent`, `interested`, `minutes` |
  | `followups` | `sent`, `replies`, `due` |
  | `quote_writer` | `made`, `approved`, `waiting` |
  | `order_desk` | `orders`, `value_paise` |
  | `lead_catcher` | `leads`, `by_source` (`[{source, count}]`) |
  | `lead_finder` | `searches`, `found`, `called` |
  | school helpers | their own counts |

- **Not built yet (later):** the helper on/off switch (`PUT /ai-team/{helper}/switch`) and the panel's read-only settings. What each helper does when it is off, and where the settings values come from, are separate jobs; until they exist the API does not pretend (no `enabled`, `can_switch` or `settings` fields). `GET /agents/switches` (the sidebar's assistant, researcher and requirement reader) is unchanged and separate.

## 3. The daily stand-up (text only)
A short written summary, in the Owner's language (4 languages; the audio version is not built):
- **Yesterday:** the flow strip's counts above zero (for a business: new leads, people called, interested, quotes, orders; for a school: enquiries, called, campus visits, admissions). A quiet day says so.
- **Now:** how many things wait for the Owner (the same count as the orange ⚑ marks).
- **Today:** the calls and follow-ups that are due (and the next call's time), the visits still to come (the first one's time).

**The text is made by code from the day's numbers, never by a model**: the same `day` the AI team page shows, for yesterday and today. It has counts and times only: **no customer name, phone number or amount is ever in it.** If there is nothing to say for a part, that part says so plainly ("Nothing is waiting for you.").

- `GET /ai-team/standup?date=&language=` (Owner, Admin) -> the stand-up of that day (default today; up to 31 days back) in that language, or `404 not_generated`.
- `POST /ai-team/standup` `{ date?, language? }` (Owner, Admin) -> makes today's again now from the real numbers, then the same shape. `date`, if sent (the page's day), must be today: any other day is `422 date_out_of_range`. Any other field is refused (422).
  - **Automatic:** the worker makes it once a day per workspace, at the business's opening time (`store_settings.weekly_hours` for today; 09:00 if no hours are set; a day the business is closed has none), in the assistant's main language (en, te, hi, kn; anything else gets English). It is made by the worker, not on a read: a GET before it exists is `404 not_generated`. Poll or reload; the page need not trigger it.
  - **By hand:** at most **3 a day** per workspace (across languages) -> `429 standup_limit` with `retry_after`, the seconds to the next Indian midnight. Making it again when the text came out identical does not count and changes nothing.
  - The worker's one is kept; a second worker save the same day never replaces it. A by-hand one replaces the stored text of that language (`by: "owner"`).
```json
{ "date": "2026-11-09", "language": "te", "generated_at": "iso", "by": "schedule" | "owner",
  "text": "…", "lines": [ { "text": "…", "source": "yesterday.flow" } ],
  "numbers": [ { "key": "yesterday.leads_in", "value": 4 } ],
  "draft": true,
  "audio": null, "audio_reason": "voice_off",
  "left_today": 3 }
```
- `generated_at` is the real time the text was made: show it as "Report ready 09:05". Before it exists there is no report: show "not ready yet", never a made-up time.
- `lines[].source` says which data each sentence came from (`yesterday.flow`, `now.needs_owner`, `today.caller_due`, `today.followups_due`, `today.visits`, `today.schedule`); `numbers` lists every number in the text (`yesterday.<step>`, `now.waiting`, `today.calls_due`, `today.followups_due`, `today.visits`).
- `draft: true` marks words not yet read by a native speaker: Telugu, Hindi and Kannada (owner, 9 Nov: Telugu and Kannada first). Show a small "draft" mark.
- `audio` is **always null** for now and `audio_reason` is `"voice_off"` (Cartesia is off by the owner's decision). Show the text, no player. The old `audio.url` route is NOT built.
- Send `language` as the Owner's app language (`?language=` on GET, `{language}` on POST). Missing = English.
- "Ask a follow-up" opens the assistant with the stand-up's date. No API change is needed for it.

## 4. Never
- No invented number, name, amount or time: every one comes from a row. The evals check 10 days × te/en.
- No lane shows a helper the workspace does not have.
- A Sales or Viewer member sees only what their role already sees.
- Nothing here changes data: the switch is the existing route.
